# Инструкции: communication

Применять вместе с [корневыми правилами](../../../../AGENTS.md).

## Контекст и этап

Перед работой прочитать [контекст communication](../../../../techDocs/services/communication/context.md) и [журнал этапов](../../../../techDocs/process/stages.md). Этот каталог подготовлен для будущей реализации; кода приложения пока нет. Установка скилов не разрешает пропуск согласований.

## Скилы по задаче

- [backend-engineering](../../../../agentSkills/backend-engineering/SKILL.md).
- [backend-review](../../../../agentSkills/backend-review/SKILL.md).
- [database-engineering](../../../../agentSkills/database-engineering/SKILL.md).
- [database-review](../../../../agentSkills/database-review/SKILL.md).

Читать только соответствующие задаче скилы до изменений. Центральная установка одна на проект; локальные копии не создавать. Подготовленные TypeScript/React/Node.js/PostgreSQL-профили относятся к кандидатному стеку: сверить с утверждённым ADR перед реализацией, при изменении стека обновить установку. Для архитектурных решений читать [project-architecture](../../../../agentSkills/project-architecture/SKILL.md).

## Обязательная передача результата

Модели генерировать по [правилам контрактов](../../../../openApi/README.md); не дублировать их вручную. Соблюдать владение данными и публичные границы модулей. Обновлять контекст и документацию своей части; записывать фактически выполненные проверки. Применять профильный review-скил, порог покрытия ≥90% по методике проекта.

## Выполнение через состояние

Все задачи с кодом, тестами, ревью, генерацией, миграциями и инфраструктурными скриптами сначала маршрутизировать через [execution-state](../../../../agentSkills/execution-state/SKILL.md), затем применять профильные скилы. Для коротких задач допустим `passthrough` по правилам скила; для длительных вести state и checkpoints. Корневой execution policy обязателен.
