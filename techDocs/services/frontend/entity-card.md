## Исходный дизайн

[Набор EntityCard в Figma](https://www.figma.com/design/qTLyRxJkaRvicTercpHUqr?node-id=17-532), страница `17:466`, guide `17:467`. Есть шесть исходных вариантов шириной 358 px и их Dark-инстансы (`17:533`). Карточки используют экземпляры Avatar и Button.

| Вариант | Действия | ID |
| --- | --- | --- |
| Person / New | Добавить в друзья | 17:479 |
| Person / Pending | Отменить заявку | 17:489 |
| Person / Incoming | Принять, Отклонить | 17:501 |
| Person / Friend | Открыть профиль | 17:511 |
| Person / Blocked | Разблокировать | 17:521 |
| Group / Member | Открыть группу | 17:531 |

В исходных карточках кнопки занимают всю внутреннюю ширину 326 px; два действия входящей заявки одинаково оформлены и стоят друг под другом. Это требует пересмотра с учётом согласованного компактного Button. В примере группы «Бегаем вместе» остались инициалы человека «АК». На странице нет отдельных широких компоновок и примеров загрузки/ошибки действия. Наличие Dark-инстансов не заменяет проверку новых состояний в обеих темах.

## Предлагаемые изменения в Figma

1. Сохранить шесть предметных вариантов и исходные ID. Использовать утверждённые Avatar, Button и токены направления 02.
2. Сделать кнопки по содержимому, без растягивания по умолчанию. Для входящей заявки: «Принять» — primary, «Отклонить» — secondary.
3. На мобильном экране располагать действия под идентификацией; переносить их при нехватке места. Для широкого контейнера показать горизонтальную компоновку: идентификация слева, действия справа. Переключение зависит от доступной ширины карточки, а не только экрана.
4. Показать загрузку конкретного действия: спиннер вместо содержимого кнопки с сохранением её размеров и доступного названия. Пока идёт запрос, исключить повторный запуск и конкурирующее действие этой карточки.
5. Показать ошибку действия рядом с действиями: «Не удалось отправить заявку. Попробуйте ещё раз» и соответствующие тексты для остальных операций. Сохранить исходное состояние и возможность повторить действие.
6. Показать длинные имена и описания, отсутствие необязательного описания, фото и fallback Avatar. Для группы использовать корректные инициалы «БВ».
7. Подготовить Light/Dark-примеры на 320/390/768/1440 px и с увеличением текста до 200%. Для мобильного контейнера с внешними отступами 16 px проверить карточки шириной 288/358 px; высота определяется содержимым.

## Поведение и границы

- `Pending` означает отправленную заявку, а не сетевую загрузку. Загрузка задаётся отдельно для выполняемого действия.
- `Blocked` в этом компоненте означает «заблокирован текущим пользователем». Карточка не раскрывает, кто заблокировал пользователя с другой стороны.
- Состояние отношений и результат операции поступают снаружи. EntityCard сообщает о действиях через callbacks, не выполняет сетевые запросы и не объявляет успех до подтверждения владельцем сценария.
- «Открыть профиль» и «Открыть группу» — ссылки с предоставленным адресом. Изменяющие состояние действия — кнопки. Не оборачивать карточку с кнопками в общую ссылку.
- Успех отражается обновлённым состоянием карточки и доступным сообщением владельца сценария. Ошибка объявляется для вспомогательных технологий; фокус после обновления не должен теряться.
- Group / Member — карточка уже доступной группы; продуктовая интеграция относится к R2. Вступление/выход из группы, чат, удаление друга и новые права в FE-19 не добавляются.
- FE-19 — библиотечная композиция. Реальные отношения, серверная проверка прав и API остаются задачами продуктовых релизов.

## План после согласования

1. Дополнить Figma по предложению и проверить структуру, темы, переносы и скриншоты; передать конкретные листы на визуальную приёмку.
2. После визуального согласования сформировать UI-схему в `openApi/frontend/`, сгенерировать модели и реализовать компонент из общих примитивов.
3. Добавить интерактивный каталог всех шести состояний, загрузки и ошибок, Light/Dark и адаптивности.
4. Проверить callbacks, блокировку повторных действий, ссылки, доступные имена, клавиатуру и сохранение фокуса. Браузерные проверки: отсутствие переполнения, переносы, обе темы, 200% текста. Покрытие собственного runtime-кода — 100% на файл по четырём метрикам; затем профильное ревью.
