## Предлагаемое дополнение InfoBanner

Сохранить 18 вариантов и их ID, существующие токены и шрифты. Ширина в приложении ограничивается контейнером; 358/600/920 — размеры примеров, а не минимальная ширина. На 320 px показать контейнер 288 px с полными текстами.

- Заголовок и описание, необязательное действие существующим Button. Размер кнопки не растягивается автоматически.
- Loading — понятный текст загрузки; не добавлять повторное активное действие.
- Error/Offline — действие «Повторить»; плашка сообщает состояние, сетевую проверку выполняет вызывающий экран.
- Empty/Permission/Success — существующая визуальная семантика и подходящие подписи; отсутствие доступа не утверждает неизвестную причину отказа.
- Показать длинный текст, длинное действие, focus/disabled/loading действия через согласованные состояния Button.
- Объявление обновлений задаётся контекстом: статичная плашка не озвучивается повторно при каждом рендере; динамический результат — polite, срочная ошибка — assertive только по необходимости. Не озвучивать одно изменение двумя live regions.

## Предлагаемое дополнение Dialog

Сохранить исходные Mobile/Desktop и композицию. Добавить листы default, sending, error, длинный контент и клавиатурный focus для обеих тем.

- На 320 px ширина 288 px, на desktop — до 480 px. Высота ограничена доступным viewport; длинное содержимое прокручивается, действия остаются достижимыми. Mobile — кнопки вертикально, desktop — в строку с переносом при нехватке места.
- Открытие переносит фокус внутрь; для отмены заявки — на безопасное действие «Оставить». Tab/Shift+Tab остаются внутри; фон недоступен для взаимодействия. Закрытие возвращает фокус инициатору, либо логичному доступному элементу, если инициатор удалён.
- Escape и «Оставить» закрывают обычный диалог. Клик по затемнению не закрывает подтверждение, чтобы не терять контекст случайно. Нажатие основного действия запускает операцию один раз.
- Sending: спиннер вместо текста основной кнопки, повторная отправка заблокирована. Закрытие доступно, но не означает отмену уже отправленного запроса; результат принадлежит вызывающему экрану и не должен теряться после закрытия.
- Error: диалог остаётся открытым, введённые данные сохраняются, ошибка видима и объявляется один раз; повторное действие доступно. Успех обрабатывает вызывающий экран.
- Доступное имя связано с заголовком; длинное составное содержимое не превращается целиком в одно описание для скринридера. Примеры поведения — технические демонстрации, не реализация API заявок.

## Приёмка

После согласования предложения дополнить Figma без удаления исходных компонентов: Light/Dark, 320 px и desktop, длинный текст/200%, состояния действий. Проверить структуру, токены, размеры, скриншоты. Перед реализацией получить визуальное согласование конкретных листов.

Затем реализация через generated-контракты, интерактивный каталог, тесты клавиатуры/фокуса/закрытия/повторной отправки/ошибок, адаптивности и объявления результата. Сохраняется порог 100% собственного runtime-кода на файл по четырём метрикам и профильное frontend-review.
