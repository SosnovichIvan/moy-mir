# FE-17 · InfoBanner и Dialog

Статус: предложение и визуальные листы согласованы сообщениями «согласовано». FE-17 реализован и подготовлен для ревью и приёмки.

## Реализация и API

`InfoBanner` и `Dialog` экспортируются из `src/shared/ui`. Конфигурации генерируются из `openApi/frontend/infoBanner.schema.json` и `dialog.schema.json`. React-слоты, callbacks и DOM refs — технические props.

- `InfoBanner`: `title`, `body`, `state` (empty/loading/error/offline/permission/success); необязательные `size` s/m/l, `announcement` off/polite/assertive и `className`. Максимальные ширины 358/600/920 px сжимаются до контейнера. `action` — слот Button, скрыт в loading. Для динамических сообщений обновлять уже смонтированную live region; экран не должен повторять сообщение в другой live region.
- `Dialog`: `open`, `title`, `confirmLabel`, `cancelLabel`, callbacks `onClose`/`onConfirm`; необязательные `description`, `pending`, `error`, `children`, `returnFocusRef`. `showModal()` блокирует фон, CSS блокирует прокрутку страницы; явное замыкание Tab/Shift+Tab удерживает фокус внутри. Безопасная кнопка получает начальный фокус, Escape и отмена запрашивают закрытие, backdrop не закрывает окно.
- В ответ на `onClose` владелец устанавливает `open=false`. Закрытие/размонтирование возвращает фокус инициатору; если он удалён — элементу `returnFocusRef`, захваченному при открытии. Запасной элемент следует держать смонтированным. Программное закрытие native dialog уведомляет владельца; устаревшее close-событие повторно открытого окна игнорируется.
- Владелец хранит draft, pending и результат запроса; закрытие не отменяет отправленную операцию. Pending блокирует Button. До обновления props владелец синхронно блокирует повторный запрос, как в каталоге. Ошибка не сбрасывает содержимое. Dialog не делает сетевых запросов.
- Длинное содержимое прокручивается отдельно, `description` остаётся коротким. При очень малой высоте доступна прокрутка всего диалога. Вложенные модальные окна и виджеты Shadow DOM не входят в текущую приёмку.

## Проверки реализации

Локально прошли lint, typecheck, форматирование, генерация без diff, production build и catalog build. Проходят 101 unit-тест, 74 browser-теста каталога и 2 smoke-теста приложения. Покрытие собственного runtime-кода — 100% statements/branches/functions/lines на файл; исключения не расширялись.

12 новых browser-сценариев: Light/Dark на 320/390/768/1440 px, имя диалога, Tab/Shift+Tab, Escape, backdrop, блокировка фоновой прокрутки, закрытие во время отправки, сохранение результата, повторная попытка, удаление инициатора, сохранение draft, длинный контент, 200% текста и forced colors. Unit-тесты дополнительно проверяют StrictMode, cleanup и stale close. jsdom подменяет отсутствующие native dialog methods; реальная модальность проверена в Chromium.

Профильное frontend-review проверило контракты, async ownership, возврат фокуса, pending, controlled lifecycle и потребителей. Найденный выход Tab за пределы native dialog исправлен и проверен. Подтверждённых замечаний не осталось. Просмотрены mobile Light, desktop Dark и длинный диалог при 200% текста. Firefox/WebKit, физические устройства и реальные скринридеры не проверены; CI фиксируется отдельно в PR.

Следующий шаг — приёмка реализации FE-17. Каталог: `info-banner--overview`, `dialog--overview`, отдельные Light/Dark stories. Далее сохранён дизайн-контракт и история подготовки.

## Предлагаемое дополнение InfoBanner

Сохранить 18 вариантов и их ID, существующие токены и шрифты. Ширина в приложении ограничивается контейнером; 358/600/920 — размеры примеров, а не минимальная ширина. На 320 px показать контейнер 288 px с полными текстами.

- Заголовок и описание, необязательное действие существующим Button. Размер кнопки не растягивается автоматически.
- Loading — понятный текст загрузки; не добавлять повторное активное действие.
- Error/Offline — действие «Повторить»; плашка сообщает состояние, сетевую проверку выполняет вызывающий экран.
- Empty/Permission/Success — существующая визуальная семантика и подходящие подписи; отсутствие доступа не утверждает неизвестную причину отказа.
- Показать длинный текст, длинное действие, focus/disabled/loading действия через согласованные состояния Button.
- Объявление обновлений задаётся контекстом: статичная плашка не озвучивается повторно при каждом рендере; динамический результат — polite, срочная ошибка — assertive только по необходимости. Не озвучивать одно изменение двумя live regions.

## Предлагаемое дополнение Dialog

Сохранить исходные Mobile/Desktop и композицию. Добавить листы default, sending, error, длинный контент и клавиатурный focus для обеих тем.

- На 320 px ширина 288 px, на desktop — до 480 px. Высота ограничена доступным viewport; длинное содержимое прокручивается, действия остаются достижимыми. Mobile — кнопки вертикально, desktop — в строку с переносом при нехватке места.
- Открытие переносит фокус внутрь; для отмены заявки — на безопасное действие «Оставить». Tab/Shift+Tab остаются внутри; фон недоступен для взаимодействия. Закрытие возвращает фокус инициатору, либо логичному доступному элементу, если инициатор удалён.
- Escape и «Оставить» закрывают обычный диалог. Клик по затемнению не закрывает подтверждение, чтобы не терять контекст случайно. Нажатие основного действия запускает операцию один раз.
- Sending: спиннер вместо текста основной кнопки, повторная отправка заблокирована. Закрытие доступно, но не означает отмену уже отправленного запроса; результат принадлежит вызывающему экрану и не должен теряться после закрытия.
- Error: диалог остаётся открытым, введённые данные сохраняются, ошибка видима и объявляется один раз; повторное действие доступно. Успех обрабатывает вызывающий экран.
- Доступное имя связано с заголовком; длинное составное содержимое не превращается целиком в одно описание для скринридера. Примеры поведения — технические демонстрации, не реализация API заявок.
