- Tablet 17:793: горизонтальная панель 720×80 px, активный пункт с мягкой фоновой плашкой.
- Desktop 17:802: боковая панель шириной 240 px с названием проекта и вертикальными пунктами, активный пункт с мягкой плашкой.
- Нет вариантов активных Requests/Profile на tablet/desktop, состояний hover/pressed/focus и отдельных сценариев длинного текста/200%.

## Согласованное дополнение

Сохранить исходные ID, палитру, токены и иконки. Дополнить набор до девяти сочетаний Layout × Active. Состояния отдельных пунктов оформить как переиспользуемые компоненты: selected/unselected × default/hover/pressed/focus; не размножать целую панель ради каждой комбинации.

1. **Mobile:** фон пунктов прозрачен во всех состояниях. Hover/pressed меняют цвет; keyboard focus добавляет контур существующим токеном focus. Это индикатор фокуса, а не фоновая плашка. Hover действует только на устройствах с hover, после touch не остаётся залипшего состояния.
2. **Tablet/Desktop:** сохранить существующие плашки активного раздела; дополнить hover/pressed/focus существующими токенами. Фокус и активный раздел независимы.
3. **Адаптивность:** mobile 320–767, tablet 768–1023, desktop от 1024 px. На mobile обычная высота 56 px; при 200% текста или длинной подписи разрешён рост, чтобы не обрезать содержание. Пункты распределяют ширину поровну. На desktop длинная подпись переносится внутри панели 240 px.
4. **Safe area:** сам компонент не добавляет safe area и не фиксируется к viewport. Оболочка размещает его и добавляет `env(safe-area-inset-bottom)` один раз; отдельный демонстрационный пример показывает отступ 34 px и резерв места под панель. Это эмуляция, не замер реального телефона.
5. **Семантика:** `nav` с доступным именем, обычные ссылки с реальными href, текущая страница через `aria-current="page"`. Tab/Shift+Tab и Enter, история браузера, модифицированный клик/открытие новой вкладки сохраняются. Не использовать tablist/menu для переходов между страницами.
6. **Границы:** демонстрационные пункты «Друзья», «Заявки», «Профиль». Активность задаётся маршрутом/владельцем; shared-компонент не делает запросов и не содержит продуктового доступа. Недоступные будущие разделы скрывает вызывающий экран; фиктивные disabled-ссылки не добавлять. Счётчики и новые разделы не входят в FE-18.

## Реализация и публичный API

Экспорты `Navigation`, `NavigationItem` из `src/shared/ui`. Конфигурации генерируются из `openApi/frontend/navigation.schema.json` и `navigationItem.schema.json`; модели вручную не дублируются. Иконки используют существующий `Icon` и экспортированные SVG.

- `Navigation`: обязательное `label` задаёт имя `nav`; `brand` по умолчанию «мой мир», отображается на desktop; `children` — пункты NavigationItem; `className` — технический binding.
- `NavigationItem`: обязательные `label`, `href`, `icon`; `current=false` по умолчанию. Текущий пункт получает `aria-current="page"`. Нативные anchor bindings (`onClick`, `target`, `rel`, `ref`) передаются ссылке. Видимая подпись задаёт доступное имя.
- Владелец экрана определяет единственный текущий пункт и разрешённые ссылки, передаёт доверенные адреса своих маршрутов. Navigation не проверяет предметные права и не загружает данные. Не передавать непроверенные пользовательские URL.
- Shared не зависит от router. Каталог показывает адаптер на штатном `useLinkClickHandler` React Router: обычный клик работает в SPA, модифицированный клик сохраняет новую вкладку. Без обработчика ссылка работает нативно. Фокус на содержимом нового продуктового экрана и scroll restoration относятся к shell/route.
- CSS переключает компоновку при 768/1024 px. Mobile: 56 px при обычных подписях, пункты минимум 48 px и иконки 22 px, подписи 12/16 px; длинный текст увеличивает высоту. Tablet: панель 80 px, desktop: ширина 240 px. Размеры текста в rem. Все состояния mobile прозрачны; forced colors дополнительно подчёркивает текущий раздел.
- Компонент находится в потоке, без fixed и safe area. Каталог отдельно демонстрирует 34 px отступа оболочки. Будущая fixed-оболочка должна резервировать фактическую высоту панели вместе с inset, включая рост текста.

Каталог: `navigation--overview`, `navigation--light`, `navigation--dark`. Все три текущих раздела, переключение длинных подписей, работающие ссылки и пример safe area. Это демонстрация UI; продуктовые страницы друзей/заявок/профиля ещё не реализованы.

## Проверки и ревью реализации

- `npm run check`: генерация без diff, lint, typecheck, форматирование, 104 unit-теста; 100% lines/statements/functions/branches собственного runtime-кода на файл.
- `npm run build`, `npm run catalog:build`: успешно.
- `npm run test:catalog`: 93 теста, включая 19 Navigation; `npm run test:e2e`: 2 production smoke.
- Chromium: Light/Dark на 320/390/767/768/1023/1024/1440 px, точные обычные размеры, длинные подписи и 200% текста без горизонтального переполнения. Проверены keyboard focus отдельно от current, Tab/Shift+Tab/Enter, история/refresh, новая вкладка, hover/pressed, touch без залипания hover, forced colors и однократный inset.
- Скриншоты mobile Light, tablet Light, desktop Dark и mobile 200% просмотрены и сравнены с согласованным направлением. При узкой ширине и 200% подписи переносятся; высота не фиксируется.
- `frontend-review`, `ui-ux-design`, `icon-system`: проверены границы, generated-модели, семантика ссылок, состояния, токены и существующие иконки. Подтверждённых дефектов в текущем объёме не осталось.

Ограничения: Firefox/WebKit, физические устройства, реальный device safe area и скринридеры не проверены. Coverage относится к runtime TypeScript; CSS-поведение проверяется браузерными тестами. Следующий шаг — ревью и приёмка FE-18, затем подготовка FE-19 EntityCard по этапам.
