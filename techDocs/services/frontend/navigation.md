# FE-18 · Navigation

Статус: предложение FE-18 согласовано сообщением «согласовано». Дополнения созданы в Figma и проверены; ожидается визуальная приёмка конкретных листов. Код FE-18 не начат.

## Источник и результат аудита

[MM / Navigation 17:803](https://www.figma.com/design/qTLyRxJkaRvicTercpHUqr?node-id=17-803) на момент исходного аудита содержал пять вариантов. Mobile: активные Friends/Requests/Profile; Tablet/Desktop: только Friends. Проверены структура и скриншоты всех трёх компоновок.

- Mobile 17:785: ширина примера 390 px, высота панели 56 px, пункт 48 px, иконка 22 px, подпись 12/16 px. Активный пункт меняет цвет иконки и текста, фон отсутствует — сохраняем явное требование пользователя.
- Tablet 17:793: горизонтальная панель 720×80 px, активный пункт с мягкой фоновой плашкой.
- Desktop 17:802: боковая панель шириной 240 px с названием проекта и вертикальными пунктами, активный пункт с мягкой плашкой.
- Нет вариантов активных Requests/Profile на tablet/desktop, состояний hover/pressed/focus и отдельных сценариев длинного текста/200%.

## Согласованное дополнение

Сохранить исходные ID, палитру, токены и иконки. Дополнить набор до девяти сочетаний Layout × Active. Состояния отдельных пунктов оформить как переиспользуемые компоненты: selected/unselected × default/hover/pressed/focus; не размножать целую панель ради каждой комбинации.

1. **Mobile:** фон пунктов прозрачен во всех состояниях. Hover/pressed меняют цвет; keyboard focus добавляет контур существующим токеном focus. Это индикатор фокуса, а не фоновая плашка. Hover действует только на устройствах с hover, после touch не остаётся залипшего состояния.
2. **Tablet/Desktop:** сохранить существующие плашки активного раздела; дополнить hover/pressed/focus существующими токенами. Фокус и активный раздел независимы.
3. **Адаптивность:** mobile 320–767, tablet 768–1023, desktop от 1024 px. На mobile обычная высота 56 px; при 200% текста или длинной подписи разрешён рост, чтобы не обрезать содержание. Пункты распределяют ширину поровну. На desktop длинная подпись переносится внутри панели 240 px.
4. **Safe area:** сам компонент не добавляет safe area и не фиксируется к viewport. Оболочка размещает его и добавляет `env(safe-area-inset-bottom)` один раз; отдельный демонстрационный пример показывает отступ 34 px и резерв места под панель. Это эмуляция, не замер реального телефона.
5. **Семантика:** `nav` с доступным именем, обычные ссылки с реальными href, текущая страница через `aria-current="page"`. Tab/Shift+Tab и Enter, история браузера, модифицированный клик/открытие новой вкладки сохраняются. Не использовать tablist/menu для переходов между страницами.
6. **Границы:** демонстрационные пункты «Друзья», «Заявки», «Профиль». Активность задаётся маршрутом/владельцем; shared-компонент не делает запросов и не содержит продуктового доступа. Недоступные будущие разделы скрывает вызывающий экран; фиктивные disabled-ссылки не добавлять. Счётчики и новые разделы не входят в FE-18.

## Приёмка дизайна

После согласования дополнить Figma: Light/Dark, три активных раздела в каждом layout, состояния пунктов, 320/390 px, длинные подписи и 200% текста; пример safe area отдельно от 56 px панели. Проверить центровку, отсутствие горизонтального переполнения, сохранение исходных ID и привязки токенов, просмотреть скриншоты. Перед кодом — визуальная приёмка конкретных листов.

При реализации: generated-конфигурация в `openApi/frontend/`, каталог и тесты переходов/истории/клавиатуры, touch, адаптивности, 200% и forced colors. Цель покрытия — 100% собственного runtime-кода на файл по четырём метрикам; затем frontend-review.

Ширина широкого демонстрационного листа не является breakpoint: на нём отдельно показаны tablet-панель 720 px и desktop-панель 240 px.

Сохранены пять исходных ID Navigation; добавлены Tablet Requests `61:212`, Tablet Profile `61:219`, Desktop Requests `61:226`, Desktop Profile `61:234`. Всего девять сочетаний Layout × Active.

Отдельные наборы пунктов: Mobile `61:274`, Wide `61:384`, по восемь вариантов selected/unselected × default/hover/pressed/focus. Это самостоятельные компоненты состояний; исходные панели пока сохраняют свою внутреннюю структуру. Используются существующие семантические токены. На mobile фон пунктов отсутствует, иконка и текст имеют одинаковый цвет состояния, focus-контур не меняет размер пункта 48 px.

Проверены структура и скриншоты всех шести листов: горизонтальных выходов за родительские контейнеры нет, длинные подписи и текст 200% видимы. В примерах mobile высота панели растёт с 56 до 72/104 px; при 320 px увеличенное слово «Профиль» переносится на две строки. Safe area 34 px показана как часть оболочки: 56 + 34 = 90 px. Примеры увеличения текста — локальные демонстрационные фреймы; автоматическое поведение в браузере ещё предстоит реализовать и проверить.
