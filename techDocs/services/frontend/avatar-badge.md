# FE-16 · Avatar и Badge

Статус: предложение согласовано пользователем 2026-09-18. Дополнения Figma созданы и проверены; листы готовы к визуальной приёмке. Реализация FE-16 не начата.

## Источники

- [Avatar](https://www.figma.com/design/qTLyRxJkaRvicTercpHUqr?node-id=17-323): 15 вариантов: размеры 32/48/64 × Image, Initials, Loading, Error, Anonymous. Исходные три component ID сохранены.
- [Badge](https://www.figma.com/design/qTLyRxJkaRvicTercpHUqr?node-id=17-351): Neutral, Pending, Success, Error, Count, CountWide. Есть Boolean-слоты иконок слева/справа и INSTANCE_SWAP.
- Используем существующие семантические токены Light/Dark и иконки MM. Поиск Avatar/Badge через search_design_system пуст; локальные компоненты найдены через Plugin API, они остаются основой.

## Согласованный объём Avatar

| Состояние | Поведение | Размеры |
| --- | --- | --- |
| Фото | Изображение заполняет круг, обрезка по центру, без искажения | 32/48/64 |
| Инициалы | До двух букв имени, по центру | 32/48/64 |
| Загрузка | Инициалы, при отсутствии имени — user; без скачка размеров и анимации | 32/48/64 |
| Ошибка фото | Тот же fallback, без значка сломанного изображения и повторов загрузки в цикле | 32/48/64 |
| Нет имени | Существующая иконка user по центру | 32/48/64 |

Показать на листах Light/Dark каждый размер и состояние. Повторяющиеся визуальные состояния нужны как сценарии проверки. Сам Avatar не является кнопкой; для действия родитель предоставляет доступное имя, клавиатуру, focus и область нажатия не менее 44×44. Рядом с видимым именем Avatar декоративный; отдельно имеет доступное имя. При смене URL загрузка начинается заново. Алгоритм инициалов: после trim берём первую букву первого и последнего слова; для одного слова — одну букву; пустая строка даёт user.

## Согласованный объём Badge

Сохранить существующие цвета и варианты. Текстовые Badge — высота от 34 px, счётчики — от 24 px. Размер не увеличивается автоматически на desktop: это не область нажатия.

- Одна цифра: круг 24×24; несколько символов: расширение по содержимому. Примеры 0, 3, 9, 10, 99, 99+.
- Числовой счётчик: целое неотрицательное значение, визуальное ограничение 99+; доступное имя содержит полное число и контекст. Скрывать ли 0, решает вызывающий экран.
- Текстовые варианты: без иконок, слева, справа, с обеих сторон. Иконки декоративные, не кнопки удаления. Иконка check применяется к успеху, close — к ошибке; pending без check.
- На ширине 320 px длинная подпись переносится целиком внутри ограниченного контейнера с ростом высоты, без обрезания содержания и горизонтального скролла. Это осознанное предложение для доступности на touch; короткие статусы остаются в одну строку.
- При увеличении текста до 200% высота может расти; требование 24×24 относится к обычному масштабу.
- Статус выражен текстом, а не только цветом. Сам Badge не создаёт live region: контекстное объявление обновления делает экран.

## Порядок приёмки

1. Сохранить существующие component IDs и экземпляры; дополнить варианты и листы для ревью.
2. Проверить структуру, привязки токенов, центровку и отсутствие пересечений.
3. Снять и просмотреть Light/Dark, 320 px, длинную подпись и увеличенный текст.
4. Передать конкретные листы на визуальное согласование; только затем реализовывать FE-16 и тесты.

Первоначальная попытка изменения Figma была отклонена автоматической проверкой разрешений. После явного сообщения пользователя «согласовано» изменения выполнены в разрешённом объёме.

Image использует созданное в Figma абстрактное растровое демоизображение 240×160, а не фотографию человека. Центральная обрезка показана на всех трёх размерах. Исходник — 50:5.

Проверены metadata, структура и скриншоты всех восьми листов. Avatar: 15 уникальных вариантов, точные квадратные размеры, центрирование и отсутствие горизонтального переполнения. Badge: сохранены шесть вариантов и API слотов; показаны четыре расположения иконок для каждого текстового статуса, 0/3/9/10/99/99+, длинная подпись и текст 200%. Счётчики одной цифры — 24×24, широкие — 30/31/39×24. Все видимые сплошные цвета новых листов связаны с существующими переменными; изображение сохраняет собственную палитру в обеих темах.

Это проверка макетов, не браузерные тесты. Проверки реального fallback, смены URL, доступных имён, увеличения текста и покрытия кода будут выполнены при реализации после визуальной приёмки.
