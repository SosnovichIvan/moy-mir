# ADR-002 · Основа frontend

Статус: блок A принят к продолжению сообщением «продолжаем»; блок B подготовлен для ревью. Начало работ разрешено сообщением «отлично. приступаем к задачам». Основание: [FE-01–FE-03](../services/frontend/bootstrap-tasks.md).

## Контекст

Нужно начать одно модульное mobile-first приложение с Tailwind и собственной библиотекой компонентов. SSR, поисковая индексация публичного каталога и независимое runtime-развёртывание UI-модулей сейчас не требуются. Реальный backend, продуктовые экраны и публикация не входят в блок A.

## Решение

- Node 24, проверенная локальная версия 24.12.0; npm 11, packageManager 11.6.2. Один приватный пакет в `apps/frontend`, собственный lockfile; отдельный monorepo runner пока не нужен.
- React, TypeScript strict, Vite 8.3.0, Tailwind 4.3.3 с официальным Vite-плагином. Остальные точные установленные версии — manifest/lockfile. Проверены engines Vite и peerDependencies Tailwind; последний допускает Vite 8.
- ESLint 10 с TypeScript/React Hooks/React Refresh, Prettier; lint и typecheck — отдельные команды. Сборщик не заменяет проверку типов. ESLint 9 отклонён после предупреждения об окончании поддержки; peerDependencies установленных плагинов допускают ESLint 10.
- Установлены React Router 8.4.0 в декларативном SPA-режиме, Vitest 5.0.1 + Testing Library, Playwright 1.63.0. Storybook с React/Vite для каталога появится в C; его версия и совместимость проверяются при подключении.
- Предлагаемая целевая матрица: Chrome/Edge/Firefox актуальный и предыдущий стабильный выпуск; Safari/iOS Safari 16.4+; Chrome Android актуальный и предыдущий. Проверки на этой матрице ещё не выполнены. Это целевая матрица, не подтверждённая поддержка: B проверяет только установленный Chromium (desktop и mobile emulation). Полная матрица остаётся проверкой E; Tailwind 4 требует современных CSS-возможностей.

## Структура и границы

`src/main.tsx` — browser entrypoint; `src/app/` — сборка приложения, router и будущие providers. Существующий `modules/` сохраняется для shell/social/messenger/planner/training/collaboration; каталоги пока содержат инструкции. Код этих модулей появляется в своих задачах.

UI-библиотека появится в `src/shared/ui/` в блоке C, с одним публичным `index.ts`. Пока пустые файлы/пакеты не создаются. `app` компонует предметные модули и shared; предметные модули используют публичные входы shared. Shared не зависит от app, предметных модулей и API-клиентов. Между предметными модулями — только публичные контракты либо композиция в app. Для будущих alias добавлять совпадающие настройки TS и Vite при появлении реального потребителя.

Публичные свойства, view-модели и генераторы разбираются в FE-12 по `openApi/README.md`. Сейчас нет ручных DTO/view-моделей, сетевых клиентов или имитации авторизации.

## Альтернативы

- Next.js добавляет серверный runtime и выбор server/client границ, которые не нужны стартовой приватной SPA. Пересмотреть при подтверждённом SSR/SEO-сценарии.
- Отдельный UI workspace-пакет полезен при нескольких приложениях-потребителях. Пока один потребитель и общий релиз; внутренний public entrypoint даёт границу без расходов на package build/publishing.
- pnpm подходит monorepo, но npm уже доступен и достаточен одному пакету. Смена возможна отдельным ADR и заменой lockfile, не совместным использованием менеджеров.

## Проверки и ограничения

Приёмка A: установка по lockfile, проверка типов, lint, форматирование, пробная сборка. Стартовый экран содержит только название; системный шрифт и минимальные цвета — временные bootstrap-стили, не реализация Figma-библиотеки. Канонические темы, локальные шрифты, взаимодействия и UI-каталог — FE-09–FE-20.

Блок B отдельно проверяет dev/preview, маршруты, конфигурацию, CI и воспроизводимость артефактов. По дополнительному запросу тестовый контур перенесён в блок A: установлены Vitest 5.0.1 и coverage-v8 5.0.1, Testing Library и jsdom. Покрытие runtime-каркаса измерено тестами, а не выводом сборки; целевой и блокирующий frontend-порог сейчас 100% на файл. Production-развёртывание, PWA и браузерная матрица ещё не проверены.

Источники совместимости: [Vite guide](https://vite.dev/guide/), [Tailwind Vite integration](https://tailwindcss.com/docs/installation/using-vite), npm metadata пакетов и фактическая установка.

## Блок B: эксплуатация каркаса

Dev/HMR, preview, вложенные маршруты и fallback проверены локально. `VITE_API_BASE_URL` валидируется при запуске Vite; по умолчанию `/api`, сетевого потребителя пока нет. CI собирает приложение и публикует отчёты/статический артефакт, без деплоя. Версии Actions выбраны по официальным инструкциям: [checkout](https://github.com/actions/checkout), [setup-node](https://github.com/actions/setup-node), [upload-artifact](https://github.com/actions/upload-artifact). Каталог добавляется в CI в C.
