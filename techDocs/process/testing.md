# Тестирование и покрытие

## Обязательное правило проекта

По прямому требованию пользователя **все сервисы и модули стремятся к 100% покрытия собственного кода тестами**. Цель — 100% lines, statements, functions и branches (либо сопоставимых метрик выбранного стека). Ранее установленный порог 90% остаётся минимальным допуском, а не целью или основанием прекратить тестирование.

Для нового и изменённого кода закрывать достижимые ветви, ошибки и граничные случаи. Если остаётся непокрытый код, в результате задачи указать файл/сценарий, причину, риск и следующий шаг. Достигнутый порог не снижать ради прохождения проверки. Общий процент не должен скрывать непокрытый модуль.

Тесты проверяют наблюдаемое поведение и контракты, а не повторяют реализацию. Процент не заменяет unit/component, интеграционные, контрактные и E2E-проверки по рискам. Авторизация, приватность, повторы, гонки и потеря связи требуют отдельных сценариев даже при 100% покрытия строк.

Исключения перечислять явно: тестовый код и его инфраструктура, декларации типов без runtime, зависимости, generated-код и статические assets. Генераторы собственного кода не исключать; generated-вывод проверять воспроизводимостью и контрактами. Нельзя исключать entrypoint или трудную бизнес-логику, добавлять ignore-комментарии либо фиктивные тесты только для повышения показателя. Конфигурация сборки проверяется запуском соответствующих инструментов; CSS и визуальное соответствие — отдельными UI-проверками.

## Текущий frontend

Vitest + V8 coverage, Testing Library и jsdom. `npm run test:coverage` включает все runtime-файлы `src/**/*.ts(x)`, в том числе ещё не импортированные тестами. Исключены только `*.test.ts(x)`, `src/test/` и `*.d.ts`. Entry point `src/main.tsx` включён.

Для текущего каркаса установлен **блокирующий порог 100% по всем четырём метрикам для каждого файла**. Это более строгий локальный порог; снижение требует отдельного согласованного решения. `npm run check` запускает coverage вместе с lint, typecheck и проверкой форматирования. Workflow FE-07 добавлен: проверяет coverage вместе со сборкой и браузерными smoke-тестами; подтверждение запуска на PR фиксируется в контексте frontend.

Отчёты: `apps/frontend/coverage/index.html`, `coverage-summary.json`, `lcov.info`. Не коммитить сгенерированные отчёты, публиковать их артефактами CI после его подключения.

Текущие 18 тестов: основной landmark и заголовок, прямые маршруты и неизвестный адрес, реальный React mount, ошибка при отсутствии контейнера, корректные и ошибочные настройки адреса API. Два Playwright smoke-теста проверяют production-preview в desktop Chromium и эмуляции Pixel 7: переходы, back, прямые ссылки, refresh, неизвестный адрес и отсутствие ошибок консоли. jsdom не проверяет фактическую вёрстку браузера, PWA или внешние API; эти проверки добавляются по мере появления соответствующих возможностей.
